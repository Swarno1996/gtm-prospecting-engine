# n8n layer

Four workflows that orchestrate the engine. n8n owns triggers, routing and alerting; the Python engine owns the logic. Each HTTP Request node calls the engine's server (`python -m gtm serve`).

| File | Trigger | Flow |
|---|---|---|
| `01_scheduled_prospecting.json` | Weekdays 07:00 | Config, `POST /prospect`, build summary, IF alert, Gmail ALERT or run summary |
| `02_dialfire_call_outcome.json` | Webhook from a Dialfire webhook task | Config, map Dialfire fields (throws on a broken contract), `POST /call-outcome`, respond |
| `03_daily_funnel_digest.json` | Daily 09:00 | Config, `GET /report`, format, Gmail digest (ALERT when nothing was created) |
| `04_error_alerts.json` | Error Trigger | Gmail with workflow name, failing node, error message and execution link |

```
01  Schedule ─▶ Config ─▶ POST /prospect ─▶ Build summary ─▶ IF alert ─┬▶ Gmail ALERT
                                                                      └▶ Gmail summary
02  Dialfire webhook ─▶ Config ─▶ Map fields (contract guard) ─▶ POST /call-outcome ─▶ Respond
03  Schedule ─▶ Config ─▶ GET /report ─▶ Format digest ─▶ Gmail
04  Error Trigger ─▶ Gmail
```

These follow the ops pattern from the inbound demo in [gtm-actions-practice](https://github.com/Swarno1996/gtm-actions-practice): loud failures through an error workflow, silent failures caught by a daily digest that alerts on zero, and a contract guard at the intake so a renamed field crashes instead of passing empty data downstream.

## Import

1. In n8n: Workflows, Import from File, pick a JSON file.
2. Create one credential of type Header Auth: name `X-GTM-Secret`, value your `GTM_SERVER_SECRET`. Select it in every HTTP Request node.
3. Connect a Gmail credential on the Gmail nodes.
4. Set `engineUrl` and `alertEmail` in each Config node, and the recipient in workflow 04.
5. Import 04 first, then set it as the Error Workflow in the settings of 01, 02 and 03.
6. For 02: create a webhook task in your Dialfire campaign pointing at the production webhook URL. Run one test call, pin the execution, and check the field names and status values against `STATUS_MAP` in the Map Dialfire fields node.

## Editing

The JSON files are generated by `scripts/build_n8n.py`. Change the script and rerun it rather than editing the JSON by hand, so ids and connections stay consistent. `tests/test_n8n.py` checks that every connection points at a real node and every node is reachable from a trigger.
